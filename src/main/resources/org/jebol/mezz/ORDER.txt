# Rebol's own library, in Rebol's own boot order.
#
# These are Rebol's files, not JEBOL's. They are loaded rather than
# rewritten because that is what the two-layer design is for: an
# implementation that can only be extended in its host language cannot
# borrow, and this is twenty-five thousand lines worth borrowing from.
# See decision 13.
#
# The order and the grouping are not JEBOL's invention. They are the three
# lists in Rebol's own `make/rebol3.nest`, and the C runs them in this
# order in `Do_Global_Block`:
#
#   mezz-base-files   rebind 1 -- new words to lib, bind deep to lib
#   mezz-sys-files    rebind 2 -- new words to sys, bind deep to lib then sys
#   mezz-lib-files    run afterwards from sys-start, into lib
#
# "-> sys" after a name is that second group. The default is lib.
#
# A file whose own header says `Type: module` overrides both and gets a
# context of its own, from which only its `Exports:` escape. That is in the
# file rather than here because the file is what declares it. See
# decision 14.
#
# JEBOL used to interleave the three groups and put the sys files last, and
# that is why base-funcs.reb went missing for so long without anyone
# noticing. It is second in Rebol's list, ahead of everything that uses
# FUNC, FUNCTION, APPLY, DEFAULT, MODULE and CAUSE-ERROR, and JEBOL carried
# its own versions of those in the prelude instead.
#
# Guessing a file's group from its name is wrong, which is why the marks are
# here as data. sys-codec.reb is in Rebol's sys list and carries the comment
# "export to lib!", and the mechanism behind that comment is its last line:
# `export [register-codec decode encode encoding?]`. EXPORT is a real
# function in sys-base.reb that copies each named word into lib. So the file
# loads into sys and four of its words reach lib because it says so.
#
# What is deliberately left out, and why:
#
#   base-collected.reb   generated from the C sources by Rebol's own build.
#                        JEBOL has no equivalent generator, so there is
#                        nothing to collect.
#   mezz-osx-dialogs.reb macOS only in Rebol. JEBOL's WINDOWS service covers
#                        what it provides, per platform, in DesktopWindows.
#
# What is changed from Rebol's copy:
#
#   prot-tls.reb         four edits that make a server's certificate and
#                        signature count. Read decision 43 before taking a
#                        newer copy, or the checks silently go.
#   mezz-banner.reb      the banner's title line says "(JEBOL port)" where
#                        Rebol's says "(Oldes branch)". Keep the edit when
#                        taking a newer copy.
#   sys-start.reb        runs a script given as an https url through the same
#                        script path as a file: header, system/script, NEEDS,
#                        module or script, QUIT. A url has no directory to run
#                        in and no local file to check, so those two steps are
#                        the file's alone. Keep the edit when taking a newer
#                        copy, or `jebol https://...` stops being a script.
#   codec-der.reb        decodes GENERALIZED_TIME as well as UTC_TIME, which
#   codec-utc-time.reb   X.509 permits for a certificate's validity, and
#   codec-crt.reb        accepts either there. A real 3.22.5 stops at the
#                        first GeneralizedTime and loses everything after it,
#                        which is what stopped a certificate from a company's
#                        TLS inspector being read at all. Keep all three edits
#                        when taking newer copies.
#   sys-load.reb         DOWNLOAD-EXTENSION checks a module's bytes against
#                        the SHA-256 in system/options/module-digests before
#                        it decompresses, writes or loads them, refuses an
#                        address outside the build that has none, and lets a
#                        mismatch or a refused network escape its TRY rather
#                        than become "module not found". The table is declared
#                        in JEBOL's sysobj.reb. Read decision 51 before taking
#                        a newer copy, or every fetched module goes unchecked.
#
# and one outside this directory, because there is nowhere else that records
# a borrowed file differing from Rebol's:
#
#   modules/unicode-utils.reb
#                        the checkout's copy closes its `make vector!`
#                        specification one bracket short, so no interpreter
#                        reads it: r3-head refuses it, and so did JEBOL until
#                        the bundled copy added the missing bracket. Upstream's
#                        master had the same fault when this was checked on
#                        2026-10-20, and r3-head reads the repaired copy.
#                        SuiteSelectionTest names this file as the one bundled
#                        module allowed to differ. Check upstream before taking
#                        a newer copy.
#
# BorrowedFilesLoadWholeTest fails if any file stops partway, and its list
# of known stops is empty. A file that stops defines nothing below the line
# it stopped on and says so nowhere else.

# prot-mysql.reb sits here, before the system object is sealed, rather than
# with the other protocols below it. It ends with
#     put system/catalog/errors 'MySQL make object! [...]
# and PROTECT-SYSTEM protects system/catalog deeply, so loading it afterwards
# leaves the file stopping on that line and JEBOL without the MySQL error
# category. Rebol never meets this: prot-mysql.reb is one of the files it
# imports on demand long after boot, and JEBOL boots it only because it has
# no IMPORT yet.
prot-mysql.reb

# -- last of what Rebol boots, because that is what it is for ----------
#
# mezz-tail.reb is the last file in Rebol's own mezz-lib-files list, and it
# has to be last of what JEBOL boots too. It sets the three aliases the rest
# of the library reads -- `codecs: :system/codecs` among them -- and then calls
# PROTECT-SYSTEM.
#
# It sits before the on-demand imports below rather than after them, which is
# where Rebol has it. Sealing the system object first is not a problem for the
# codecs that follow, because PROTECT-SYSTEM ends by naming the one part they
# write to:
#     unprotect/values [system/options system/catalog/file-types]
# and REGISTER-CODEC does `append append system/catalog/file-types ...`.
mezz-tail.reb

# -- what Rebol imports on demand, and JEBOL boots ---------------------
#
# Rebol reaches every one of these through IMPORT, after the boot has ended.
# JEBOL has no IMPORT yet, so a codec that is not booted cannot be reached at
# all. They come after mezz-tail.reb because that is where Rebol's own
# imports happen: `codecs` and `keys-of` are its aliases, and a file loaded
# before it cannot see them -- which is what stopped codec-image-ext.reb.
#
# mezz-osx-dialogs.reb is deliberately not here. It opens by unsetting
# REQUEST-DIR, REQUEST-FILE and REQUEST-COLOR and defining its own, each of
# which shells out to `osascript`. JEBOL serves those three through the WINDOWS
# service and its port, which works on every platform and asks the host's grant
# first; the vendored file works on one platform and asks nobody. It read as
# nothing until raw strings arrived -- its AppleScript is written as `%%{...}%%`
# -- and loading it then replaced the port with a shell command.
codec-ar.reb
codec-bbcode.reb
# codec-der.reb before codec-crt.reb, which opens with
# `der-codec: system/codecs/DER`. Alphabetical order puts them the other way
# about, and Rebol never has to decide: it imports each on demand, so a codec
# that needs another is asking for it by the time it runs.

codec-crt.reb
codec-ico.reb
# codec-image.reb before codec-image-ext.reb, for the same reason DER comes
# before CRT. The extension opens each of its blocks with `if find codecs
# 'png`, and codec-image.reb is what registers png, jpeg, gif, bmp, dds and
# tiff -- so loaded the other way about every one of those guards was false
# and every `put` was skipped without a word said. That is what left the image
# codecs with no `size?`, and four whole groups of the codecs file with
# nothing to run.
