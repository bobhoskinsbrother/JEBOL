# What Rebol-Brotli 0.1.0 and Brotli's streaming API answer

The reference for goal 1b. `generate.sh` writes every file here from two
sources fetched by tag:

- **Rebol-Brotli 0.1.0** (https://github.com/Oldes/Rebol-Brotli, MIT), the
  tag R3's `system/modules/brotli` address names. Its C is compiled against
  `rebol3-source/src/core/brotli/`, Brotli 1.2.0, into a `.rebx` loaded into
  `./r3-head`. No release binary is run. Its header and command table are
  regenerated by running its own `src/brotli-rebol-extension.r3`, as its build
  does.
- **Brotli's own streaming API**, driven by `stream-table.c`, compiled against
  the same 1.2.0 with `c/dec/decode.c` and `c/include/brotli/decode.h` taken
  from Brotli `v1.2.1`. Those two files are the only difference between the
  releases, and they are the fix for CVE-2026-111497 (Google's commit
  `0ed4268`). So the table holds the encoder JEBOL's port follows and the
  decoder without the CVE.

| File | What it holds |
| --- | --- |
| `module-answers.r3`, `.txt` | the module, `version`, one-shot `compress` and `decompress` at every level and size boundary, and `compress 'br` before and after import |
| `module-streams.r3`, `.txt` | twelve scenarios, each in a process of its own: encoders and decoders through `write`, `/flush`, `/finish` and `read`, the handle fields, and the errors; addresses in a mold are `0#<address>` |
| `module-stream-case.r3`, `.txt` | single streaming cases, each in a process of its own; a crash is `crashed` |
| `stream-cases.txt` | the cases the table runs, one a line, read by `stream-table.c` and by JEBOL's tests alike |
| `stream-table.c`, `stream-table.tsv` | each case's calls to `BrotliEncoderCompressStream` or `BrotliDecoderDecompressStream`, and each call's output length and 64-bit FNV-1a digest; and each `cve` case's stream and 1.2.1's answer to it |

`text` is the generator both sides share: `x` starts at 12345 and becomes
`(x * 1103515245 + 12345) and 2147483647` for each byte, which is
`"the quick brown fox jumps over a lazy dog "` at `(x >> 16) mod 42`; `noise`
is `(x >> 16) and 255`. `maps` is the front of `../mapsdatazrh-first-30k.bin`,
the slice of Brotli's own corpus already checked in for the one-shot port, so
the streaming API meets real structured data at every level 0 to 11.

A `cve` case is built bit by bit, by `stream-table.c` and by JEBOL's
`BrotliBlockSwitchStreams` alike: one meta-block of dictionary words that
transform 34 leaves empty, each costing a command and a distance and no output,
then one four-letter word. With one command block type the 2^24+1st command asks
for a switch; with two, the first command block is longer than 2^24 and the
2^24+1st distance asks. 1.2.1 decodes 2^24 and refuses the next with
`BLOCK_SWITCH` (-17). Literals cannot reach their cap: a meta-block holds at
most 2^24 bytes. The streams are 30 MB, so they are made, not stored.

## What the extension's C does that JEBOL does not copy

**Every scenario and case runs in a process of its own,** because the C
corrupts memory silently: run one after another in one process, a decoder that
streams correctly on its own lost and repeated bytes (300,002, 300,001 and
301,672 for 300,000) and R3 stopped with "Overflow Series". Nothing in these
transcripts was produced after a crash or a corruption in the same process.

The table, not the extension, is the authority on a stream's bytes: it calls
Brotli's API directly, and the extension's level 0 and 1 path cannot be run to
the end.

| Case | What the C does | Seen in |
| --- | --- | --- |
| an encoder at level 0 or 1 that has data, finished with `none` | passes `NULL` as the next input; the fast path reads through it and crashes | `module-stream-case.txt` |
| a stream with a block switch where a category has one block type | CVE-2026-111497: reported as needing more input, so the streaming decoder writes past its 8-byte buffer | Google's commit `0ed4268`; the table's decoder has the fix |
| `d/mode: 1` or `d/size-hint: n` on a decoder | `RX_Init` registers the decoder with the encoder's `REBHSP` still holding the encoder's `set_path`, so it calls `BrotliEncoderSetParameter` on a decoder's state | `module-streams.txt` answers the value; JEBOL answers it too and changes nothing |

JEBOL finishes a level 0 or 1 stream given `none` as it finishes one given
`#{}`, and its decoder gives out what Brotli's streaming API gives out for the
same pieces of input, which is what the table records.

## What it does that JEBOL does copy

- **Levels clamp two ways.** `compress` passes its level through a `REBCNT`, so
  `-1` is the C's "none given" and becomes 6, and every other negative becomes
  11. `make-encoder` clamps a signed level, so every negative is 0.
- **`decompress` short-cuts.** An empty input, `/size 0`, `/part 0` and a
  negative `/part` answer `#{}` without decoding; bytes after the end of a
  stream are ignored; `/part` that cuts a stream short fails.
- **The fields are R3's `PD_Handle`.** `finished` reads on both handles;
  `mode` and `size-hint` set on an encoder and do not read (`invalid-path`);
  setting `finished` is `bad-path-set`; a field of the wrong type is
  `bad-field-set`.
- **A fresh handle has no buffer.** `write` of `none` and `read` before any data
  answer none and leave the encoder unfinished.
- **A damaged stream is not an error to `write`.** A decoder given bytes that
  are not a stream, or a stream cut short, answers `#{}` from `write/finish` and
  never reports `finished`; only `decompress` fails.
- **`write` answers the handle** unless `/flush` or `/finish`, and then a copy
  of everything decoded or encoded since the last answer. A decoder's `/flush`
  and `/finish` change nothing about the decoding.
- **Importing replaces `br`.** The extension's `compress` writes the same bytes
  as the core's at every level and sample size, so `compress 'br` after import
  is unchanged. A `decompress 'br` it refuses is R3's `bad-press` carrying
  `BrotliDecoderGetErrorCode`: 2 for a stream cut short, since the C stops on
  needing more input, and the format error's own number otherwise.
- **`Accept-Encoding` gains a second `br`.** It is `gzip,deflate,br` before
  import, because `prot-http.reb` adds `br` when the catalog has it, and
  `gzip,deflate,br,br` after: the module's check only looks at the item after
  the first comma.
- **The module, imported by path, has no name** and its options are
  `[extension private]`. Imported through R3's address it would be named
  `brotli`; that path downloads a release binary, which this project never
  runs, so it is not recorded.

## The boundaries, and what covers each

| Boundary | Covered by |
| --- | --- |
| every level 0 to 11, -1, -2, 12, 99 | `module-answers.txt`, `module-streams.txt`, the table's `finish` cases |
| 0 to 3 bytes; either side of 2^15, 2^16, 98,304 and 2^17; 2^22, the window | the table's `finish` cases at every level |
| chunks of 1, 1,000, 65,535 to 65,537 and 98,304 | the table's `process:` cases |
| a flush after every chunk; a flush of nothing; a read after every chunk | the table's `flush:` and `read:` cases; `module-streams.txt` |
| `mode` 0, 1 and 2 | the table's mode cases, text and noise |
| a size hint of none, 0, under, equal, over, 2^32-1, and set late | the table's hint and `late-hint:` cases |
| incompressible input | the table's `noise` cases |
| decoding whole and in chunks of 1, 7, 1,000 and 65,536 | the table's `decode` cases |
| a string input, wide, and not at its head | `module-answers.txt`, `module-streams.txt` |
| a handle of another kind | `module-streams.txt` |
| CVE-2026-111497 | to be crafted in step 4, with the fixed decoder's answer |
