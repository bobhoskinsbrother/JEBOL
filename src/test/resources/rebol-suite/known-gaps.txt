# func-test.r3's five remaining entries are one behaviour: R3 binds a
# function's body block in place when the function is made, and JEBOL binds it
# by name at each call.
#
# The difference is invisible until a body block is shared or changed after the
# fact, which is exactly what these test. `make function! reduce [[x] body]`
# twice over the same block leaves the block bound to whichever function was
# made last, so calling the first one raises; and `change f-body 'value` puts
# an unbound word into a body that is already running, so it resolves to the
# global `value` rather than to the argument of the same name.
#
# Matching it means relative binding -- words bound to a position in the
# argument list rather than to a frame, resolved against whichever frame is
# current. That is R3's binding model and not this one, and swapping it is a
# change to how every function in the interpreter is bound. Five assertions do
# not pay for it. Written down here so the next person does not start it
# thinking it is a defect in MAKE.
#
