# The one checksum-test.r3 entry left is not a checksum defect, and no work on
# CHECKSUM will retire it.
#
#   --assert binary? file-checksum system/options/boot 'md5
#
# `system/options/boot` is the launcher JEBOL writes for itself, and its job is
# to be handed to the host shell rather than read through the sandbox. LAUNCH is
# `reduce [system/options/boot script]`; Rebol's own call-test.r3 and
# module-test.r3 re-launch through it a dozen times; and the launcher carries
# `--root` so a child interpreter inherits the parent's confinement, which is
# the rule ASecondInterpreterIsConfinedAsThisOneIs in spec/embed.allium. So it
# has to be a real executable file on the host, outside whatever directory the
# script can see. `BootProcessFromTheSourceTest` pins all three of those.
#
# This assertion asks to *read* it. With `--root /` it passes here exactly as it
# does on ./r3-head; under the suite host it cannot, because the file is outside
# the root on purpose. Making the field name something inside the root, or none,
# would break LAUNCH and confinement propagation to retire one assertion.
#
# It stays here rather than in fails-on-rebol-too.txt because that file's rule is
# that every line in it was run through ./r3-head and failed there. This one
# passes there.
#
# Relative binding was built on 12 September 2026 and the five func-test
# entries that needed it are gone. What it is, and what it cost:
#
# A function's body is bound when the function is made, to a context holding
# the words its spec declares, and a call lends that context its frame. So the
# same bound word reads a different value each time round and the innermost
# call's inside a recursion -- and a word put into the body afterwards was
# never bound, so it reads the global of its name. A body shared between two
# functions belongs to whichever was made last, and calling the other raises
# not-defined.
#
# A closure is bound the same way and then copied per call, because its frame
# outlives the call. By binding rather than by name, which is what keeps the
# two rules above true of a closure as well.
#
# Four subsystems each held their own end of the model and each had to be
# brought into line. Written down because the first attempt broke 513 tests
# and these were the whole of it:
#
#   - Context.set did not follow the frame a call had lent, so PARSE's
#     `copy word` wrote into the template instead of the call. That one was
#     latent before this work and would have bitten the recursion case.
#   - APPLY and the natives call functions by a second path that kept its own
#     books on which frames were open, so a call through it while another was
#     open trampled the pointer. Both paths now push the same record.
#   - CONTEXT? reads the function off the frame, so the declared words had to
#     carry it, and to say the call is over when none is running.
#   - COMPOSE/DEEP shared a nested path between two answers where the C copies
#     it -- `// Include PATHS` is the C's own comment -- so binding one
#     function's body reached into another's.
#
