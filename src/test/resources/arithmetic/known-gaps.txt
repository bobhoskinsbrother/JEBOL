# Arithmetic pairings JEBOL does not yet answer as a real 3.22.5 does.
#
# Each line is the left-hand side of a line in every-pair.recorded. The test
# asserts that every pairing NOT listed here matches the recording exactly,
# and that every pairing that IS listed still diverges -- so fixing one makes
# the build fail until its entry is deleted, and the list can only shrink.
#
# 277 of 810 when the recording was made. 25 now, and all 25 are one cause.
#
# POWER is declared `power: action [number [number!] exponent [number!]]`, so
# calling it by name checks the argument against number! and answers
# expect-arg. Calling it as ** does not check: `power 1.2.3 2` is expect-arg
# and `1.2.3 ** 2` is cannot-use, from the same function and the same
# arguments. Measured, both ways, for tuple, money, time, pair and string --
# the prefix name always answers expect-arg and the operator always reaches
# the datatype's own dispatch.
#
# So an op! call in R3 skips the argument typecheck that a named call makes.
# Declaring the typespec here fixes these 25 and breaks ** for every operand
# the typespec is narrower than the dispatch, which Rebol's own tuple-test
# catches. Making operators skip the check is an evaluator-wide change: it
# would alter + - * / too, and nothing has measured what those answer for an
# operand outside their declared types. That wants its own recording first.
